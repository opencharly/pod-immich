# 2026.328.1908 — fix(volumes)!: wire the ML cache through HF_HOME, drop the dead cache volume

## Summary

Three volume-wiring corrections, each measured against the built `immich-cdi` image (Immich v3.4.2), plus the documentation that described them wrongly.

1. **The ML model cache is now wired through `HF_HOME`.** The ML venv ships `huggingface_hub`, which honours `HF_HOME` (9 references in the venv) and reads `TRANSFORMERS_CACHE` nowhere (0 references). The candy set the retired variable, so the `models` volume was never written — huggingface_hub resolved its cache under `$HOME/.cache` instead (measured: `/root/.cache/huggingface` with an unpinned container root, `/home/user/.cache/huggingface` with HOME pinned), i.e. inside the container's writable layer, re-downloaded on every rebuild.
2. **The `cache` volume is removed.** Nothing in the image references `/home/user/.immich/cache` (grep over `/opt/immich`, `/etc/supervisord.d`, `/usr/local/bin`), and Immich has no cache-folder setting — thumbnails and encoded video live under `IMMICH_MEDIA_LOCATION`. The volume and its `mkdir` step are gone.
3. **`import` and `external` are documented as what they are**: an operator staging directory and a DB-configured external-library root (`importPaths` on a library record), neither wired by environment.

Also: `AGENTS.md` claimed a check asserts the mounted library dir — none touches it; both skill files carry the corrected volume/env tables.
