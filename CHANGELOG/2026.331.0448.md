# 2026.331.0448 — feat(box): the immich-cdi image and its disposable bed

## Summary

Move the `immich-cdi` box and its `check-cachyos-immich-pod` bed out of `distro-cachyos` into the repo
that owns the service (`AGENTS.md` "Repo classes and naming": a bed lives with the thing it tests; a
`distro-*` repo holds the distro family, not one service's box).

**The box** composes the LOCAL `immich` candy — the box proves this tree, not a pinned release of
itself — plus the two genuine composition choices the image makes: `layer-vectorchord` (the immich
candy detects VectorChord *conditionally*, and this image chooses **with** it) and `pod-dbus`.

**The project header, line by line** (the distro copy inherited all of it from its parent project):

- `defaults.platform: [linux/amd64]` — the arch the images above it build for.
- `defaults.tag: auto`, `defaults.registry: ghcr.io/opencharly` — a build in this repo names and
  publishes itself the way every charly repo does, without a parent defaulting it.
- `defaults.build: [pac]` — the package format the Arch base resolves.
- `defaults.builder.{aur,cargo,npm,pixi}: arch.arch-builder` — **needed, not cosmetic**: a builder map
  does not cross a namespace boundary, so a project composing an imported base must declare it or the
  pixi/npm candies fail with "no builder.pixi configured".
- `defaults.merge.auto: false`, `merge.max_mb: 128` — the inheritance-time image merge policy the
  distro project used for this family; kept so the box behaves identically here.
- `import: podcdi / cachyos / arch` — the CDI pod base and the CachyOS base as **namespaced imports at
  the project root** (a namespace mounted by a discovered document does not resolve a box's own
  `base:`).
- `discover: path: box, recursive: true` — **load-bearing**: without it `box/immich-cdi/charly.yml` is
  never discovered, and the box simply does not exist.

**Moving the box also removes a drift it carried.** The distro copy pinned four layers explicitly at
tags OLDER than the ones the immich candy's own `require:` names:

```
box (distro copy)                        candy require:  (pod-immich@main)
layer-nodejs      v2026.272.0322    vs   layer-nodejs      v2026.314.0707
layer-supervisord v2026.271.1817    vs   layer-supervisord v2026.314.0710
pod-postgresql    v2026.272.0233    vs   pod-postgresql    v2026.327.1758
pod-redis         v2026.272.0226    vs   pod-redis         v2026.327.1753
```

A composition that contradicts its own candy is two sources of truth for four versions, so those
pins are gone and the candy's `require:` governs. **Measured, and stated without over-claiming:** in
this project the old pins produce NO additional resolver notice — with the `cachyos` import dropped
and only this repo's boxes in scope, the pinned copy validates `rc=0` with exactly one notice
(`layer-supervisord … box=arch-coder`, from the `arch` import) and none naming `immich-cdi`; the
unpinned copy measures identically. The notice I expected was not reproducible here, so the reason
to drop the pins is the contradiction above, not a notice.

One documentation correction travels with the bed: its description listed `agent-forwarding` as part of
the image, and neither the box, the candy nor its `require:` composes it. The word is removed rather
than copied.

It also adds the canonical `.gitignore` (copied from `distro-cachyos`); this repo had none.

to chase the umbrella roster's name references in the same window as the deletion of the distro copy.
