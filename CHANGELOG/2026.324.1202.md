# 2026.324.1202 — fix(immich): dial the composed database over its unix socket, not TCP 127.0.0.1

## Summary

**The Immich server dials a TCP database that cannot exist: the composed `pod-postgresql` starts its cluster with `listen_addresses=''`, so it serves the UNIX socket `$HOME/.postgresql` and binds no TCP port. The server therefore crash-loops on `ECONNREFUSED 127.0.0.1:5432` and never serves `/api/server/ping`.**

Measured, not inferred. In a live pod (`opencharly/distro-cachyos` `check-cachyos-immich-pod`, run `2026.324.0918`, image built from `pod-immich:v2026.324.0914`):

```console
  PASS  check the Immich Node server bundle is built into /opt/immich/server
  FAIL  check service=immich-server  [immich-server-running]  running=false, want true
  FAIL  check http://127.0.0.1:${HOST_PORT:2283}/api/server/ping  [immich-http-ping]  read tcp …: read: connection reset by peer
  PASS  check the supervised immich-ml service is running  [immich-ml-service-running]  ok
```

and the container journal shows why:

```console
[157] LOG:  listening on Unix socket "/home/user/.postgresql/.s.PGSQL.5432"     # the ONLY listener
Error: connect ECONNREFUSED 127.0.0.1:5432
2026-11-20 09:34:18,810 WARN exited: immich-server (exit status 1; not expected)   # ~1s after the socket came up
```

The candy already knows the socket is the interface: `immich-db-migrate.sh` runs `psql -h "$SOCKET_DIR"`, and `immich-server-start.sh`'s readiness loop runs `pg_isready -h "$HOME/.postgresql"`. The one line that disagreed was `DB_HOSTNAME: "127.0.0.1"`, so the wrapper waited for the socket and then handed the server a hostname that resolves to nothing.

Three changes, one file:

1. `DB_HOSTNAME` is no longer a TCP host — it is the pre-exec default (`~/.postgresql`), with a comment saying the wrapper replaces it at runtime and why a loopback hostname cannot work.
2. `immich-server-start.sh` resolves the socket directory from `HOME` (the same `${HOME:-/home/user}` convention `immich-db-migrate.sh` already uses), uses it for the readiness probe it already had, and `export DB_HOSTNAME="$SOCKET_DIR"` immediately before exec — so the client follows the deploy user instead of a hardcoded path.
3. TWO build-scope assertions, split so each can actually fail on its own regression:
   - `immich-server-db-unix-socket` (positive, `file.contains`): the wrapper still carries the socket wiring (`export DB_HOSTNAME=`, `SOCKET_DIR=`, `/.postgresql` — `$`-free fragments, because an assert-only step substitutes the runner's auto-exported variables instead of comparing them).
   - `immich-server-db-no-loopback` (negative, `command`): `! grep -Eq 'localhost|::1|127[.][0-9]+[.][0-9]+[.][0-9]+' /usr/local/bin/immich-server-start.sh`. This is the arm the round-1 review found missing: a `contains` of fragments is satisfied by `export DB_HOSTNAME="127.0.0.1"` too, so the positive arm alone would stay green through exactly the regression this change exists to prevent. The pattern covers EVERY loopback spelling a client can be handed — the whole `127/8` dotted-quad family, `localhost`, and the IPv6 `::1` — because round-2 review showed that refusing only the literal `127.0.0.1` left `localhost` green.


## Change classification

**candy (build-step config + TWO plan assertions)** — `charly.yml` only: the env default, the generated start wrapper, and the pair of assertions that pin its transport (one positive, one negative). No packages, no services, no pins.

**Closes / relates to:** fixes `opencharly/pod-immich#17` (the filed defect, with the full journal). Relates to `opencharly/pod-postgresql#5` (filed: that candy's description promises TCP `127.0.0.1:5432` while its entrypoint binds `listen_addresses=''` — the doc/behaviour divergence that let this mismatch ship).

**Breaking change + rollback:** none. The subject carries no `!`: no name, path, port or shape changes, and the wrapper sets the runtime value before the server starts. A consumer that was (wrongly) relying on the TCP default was already broken — it could not connect at all. Rollback is a revert; the candy returns to the crash-looping state, which is why the assertions are part of the fix rather than a follow-up.
